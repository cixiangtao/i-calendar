# 版本规划

## 当前状态：1.0.4

已实现 Tauri Mac 菜单栏月历、独立公农历与调休核心、共享 React 界面与网页版官网。iOS 入口和配置已接入，完整 Xcode 工程生成与设备验证尚未完成。用户于 2026-11-13 明确要求直接发布正式版，Mac arm64 1.0.0 已按本地签名、未公证方式发布，公开 GitHub 仓库、Release、正式更新源与 GitHub Pages 官网已由统一 Actions 流程交付。验证详情见[验证记录](验证记录.md)。

1.0.2 已将右上停靠、280ms 原生滑入、180ms 向右滑出与快速重开保护纳入正式版本，沿用既有更新公钥与分发方式。

1.0.3 增加浅深色独立的 37 项高级配色、对比度提示与恢复入口；优化弹窗关闭后恢复日历，以及设置底部的红色退出操作，沿用统一 Actions 发布入口。

1.0.4 将高级配色收敛为八个主色，统一内置主题、派生规则和首帧 CSS，并预留版本化主题包数据契约。2026-11-16 起，每轮改动验证后直接发布正式版，不再单独确认发布。

2026-11-13 已确认：首个 1.0 交付 Mac＋网页版，iOS 在后续版本交付，不作为首个 1.0 的必过项。以上是阶段目标，不承诺具体发布日期。首轮结果与剩余条件见[1.0 验收清单](1.0验收清单.md)。

Mac 自动更新已接入“自动检查、用户确认后下载并安装”的流程。1.0.0 已配置正式公钥和 HTTPS 更新源，公开更新包已通过官方验签；真实安装位置的跨版本升级、重启与偏好恢复仍需后续实机验收；后续版本通过签名更新包分发，详见[自动更新](自动更新.md)。

此前 0.1.0 已进入功能冻结与实机验收：以源码 `84cf758` 和独立保存的 0.1.0 产物作为[候选体验基线](候选版体验.md)。优先处理阻断问题，完成日常驻留、系统变化、自启与更新实机验证，再落实正式发布配置；这份历史基线继续保留；随后用户明确要求直接发布 1.0.0，覆盖原先等待长期验收的门槛。

## 官网首屏

首屏就是日历：月历、公历与农历、节气与节日、休假与补班，以及切换月份和回到今天的操作。访问后直接可用。下载、项目介绍、数据来源和其他说明放在首屏之后或次级入口。

## 开发方式

每个经过验证的逻辑修改都创建 commit，描述使用中文；不把互不相关的变更合并为一次大提交。版本号根据实际完成范围升级，不为提前发布而跳到 1.0。
