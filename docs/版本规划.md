# 版本规划

## 当前状态：2.2.0

已实现 Tauri Mac 菜单栏月历、独立公农历与调休核心、共享 React 界面与网页版官网。iOS 入口和配置已接入，完整 Xcode 工程生成与设备验证尚未完成。用户于 2026-11-13 明确要求直接发布正式版，Mac arm64 1.0.0 已按本地签名、未公证方式发布，公开 GitHub 仓库、Release、正式更新源与 GitHub Pages 官网已由统一 Actions 流程交付。验证详情见[验证记录](验证记录.md)。

1.0.2 已将右上停靠、280ms 原生滑入、180ms 向右滑出与快速重开保护纳入正式版本，沿用既有更新公钥与分发方式。

1.0.3 增加浅深色独立的 37 项高级配色、对比度提示与恢复入口；优化弹窗关闭后恢复日历，以及设置底部的红色退出操作，沿用统一 Actions 发布入口。

1.0.4 将高级配色收敛为八个主色，统一内置主题、派生规则和首帧 CSS，并预留版本化主题包数据契约。当时的发布授权见[验证记录](验证记录.md)。

1.0.5 接入 release-it，统一本地多端版本准备、质量门禁、发布提交与当前标签的原子推送；正式构建、签名、Release 和官网继续由唯一 GitHub Actions 流程执行。

## 交付方式

2026-11-18 起，修改完成后先进行本地验证并汇报，由 IKUN 同学决定当次是否发版。改变 Mac/iOS 或跨端共享能力与应用交付内容的改动，在获得明确同意后可合并为一次应用发版。官网展示与 Web 专属改动按官网部署流程处理。纯文档、协作约定、验收记录及不影响应用产物的流程维护验证后提交并推送。

应用版本按 SemVer 2.0.0 选择，同一批改动采用最高级别。兼容修复递增修订号，新增兼容功能或弃用公开能力递增次版本，不兼容变化递增主版本。详细口径见[发布约定](发布约定.md#应用版本号)。

官网已接入独立的 GitHub Pages 流程，正式应用发布也可同步部署官网。Mac 下载入口指向 GitHub 最新公开正式版。详细范围见[发布约定](发布约定.md)。

## 官网首屏

首屏就是日历：月历、公历与农历、节气与节日、休假与补班，以及切换月份和回到今天的操作。访问后直接可用。下载、项目介绍、数据来源和其他说明放在首屏之后或次级入口。

## 开发方式

每个经过验证的逻辑修改都创建 commit，描述使用中文；不把互不相关的变更合并为一次大提交。应用发版获同意后按实际范围递增版本，官网独立部署与纯文档提交不递增应用版本。
