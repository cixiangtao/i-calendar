# Mac 开机自启

## 使用方式

在“设置 → 常规 → 启动”中切换“开机自启”。功能仅出现在 Mac；网页版与 iOS 不显示该设置。

- 首次使用不会自动注册。开关读取本机启动项记录，已有注册状态会保留。
- 开启后，在当前用户登录 Mac 时于菜单栏后台运行，不自动展开日历；点击菜单栏图标再打开面板。
- 关闭后移除当前用户的自启注册；当前运行的日历不会退出。
- 修改完成后重新读取系统记录，读写期间禁用开关。失败显示错误并重新查询，无法确认时显示未知状态并允许“重新读取”。
- 开发模式、未打包的可执行文件以及隔离冒烟模式不能注册启动项。需先退出开发实例，再打开打包后的 Mac 应用使用。

建议将应用放到固定位置（如“应用程序”文件夹）再开启。启动项记录的是应用的实际路径；移动或重命名应用前先关闭自启，移动后重新开启。同路径更新应用可沿用已有注册。

## 平台实现

使用 `tauri-plugin-autostart 2.7.0` 的 `MacosLauncher::LaunchAgent`，通过 Rust 受限命令查询、启用和关闭，不给界面开放插件的通用命令。

- 启动项标识：`local.icalendar.app`，与当前应用标识保持一致。
- 注册文件：`~/Library/LaunchAgents/local.icalendar.app.plist`。
- 程序参数：应用绝对路径与 `--autostart`。
- 自启状态由系统注册文件管理，不写入 `CalendarPreferences`；导入偏好、恢复旧缓存或在网页修改设置不会替用户开启系统自启。
- 开机自启的实际含义是“用户登录后启动”，不是在登录前运行的系统服务。开关读取的是 LaunchAgent 注册记录；若用户在 macOS 系统设置中禁止了后台项目，注册记录仍可能存在，实际启动行为还受系统设置控制。
- 不调用 AppleScript，不申请“自动化”权限，不联网，不需要管理员密码。

Mac 窗口在创建时保持隐藏，普通启动在前端准备完成后打开；携带 `--autostart` 时保持隐藏。单实例回调也识别该参数，后台重复启动不会把现有日历弹到前台。菜单栏仍完成初始化并持续刷新时间。

历法核心不依赖自启能力。共享 UI 通过 `LaunchAtLogin` 平台接口读取和修改注册，状态控制器处理并发、失败和重新查询；进入设置与窗口重新获得焦点时刷新。

## 验证边界

- 状态测试覆盖读取、开关、外部记录变化、读写互斥、系统拒绝、读取失败恢复及不支持的平台。
- Rust 测试覆盖自启参数判定、应用包路径和开发/隔离模式保护。
- `pnpm run check:mac` 分别启动普通隔离实例与带 `--autostart` 的隔离实例。后者先检查面板保持隐藏，再主动展开并执行原有 WKWebView、共享核心、IPC 与窗口生命周期验证。
- 两种冒烟实例都禁用自启注册，测试不会修改用户的 LaunchAgents。浏览器界面验证采用内存模拟，不代表系统已开启。
- 用户实际登录后的启动、macOS 后台项目控制以及正式签名分发环境中的行为，仍需发布前实机验收；不会为验证本功能而重启电脑、注销登录或替用户开启自启。
