# 日出日落与定位

在“设置 → 常规 → 日出日落”点击“使用当前位置”，或手动选择国内城市及部分区县参考点。取得有效位置后，首页仅用一行显示所选日期的日出、日落与白昼时长，切换日期随之更新。地名、定位精度和时间、手动参考点标识与计算说明集中在设置；时间统一为北京时间。无位置、关闭或自动定位未成功时不显示首页占位。

## 自动定位与地名

- 计算直接使用系统返回的 WGS84 经纬度，不按城市名称统一替换成市中心坐标。同一城市内东西位置不同，计算结果也随实际坐标改变。
- Mac 使用系统 Core Location；Web 使用浏览器定位。iOS 原生入口及使用期间权限配置已接入，但当前环境没有完整 Xcode/iOS SDK，未宣称编译、模拟器或真机通过。
- Mac 系统地名解析尽力返回省、市、区县及道路，不取门牌和住宅名称。地名解析失败不影响坐标，回退到“当前位置”或离线参考点的“附近”标签。Web 不额外向第三方逆地理编码接口发送坐标，使用附近参考点提示，不能将其当成街道级地址。
- 精度由系统、设备、网络环境及用户授权决定，不能承诺一定达到街道级。设置中显示系统报告的米/公里精度；超过 10 公里时提示当前定位较粗。请求高精度不等于系统必定返回高精度，更精细的地名也不会提高坐标本身的精度。
- 返回的负精度、非有限或越界坐标、超过两分钟的旧位置不会当作新定位。等待权限或位置有超时，可主动重试或手动选择。

## 刷新、取消与隐私

定位默认关闭，升级或首次打开不会主动弹出定位权限框。用户明确启用后，只有页面可见且有焦点时才提供自动刷新机会，同一会话半小时限频；后台启动、隐藏或失焦状态不发起新的自动请求。每次只取得一个位置结果，不进行持续追踪。

首次点击“使用当前位置”或“申请定位权限”会主动请求系统或浏览器授权，允许后才获取位置；Mac 先激活应用并等待进入前台，再申请使用期间权限。自动刷新只使用既有授权，不弹新权限。系统已拒绝或关闭定位服务时，Mac 提供“打开定位设置”，修改后点击“重新检查权限”；系统拒绝后不支持应用强制再次弹框。浏览器拒绝需在网站权限中恢复，设备限制单独说明。

拒绝或失败后，本次会话不继续自动重试，保留主动恢复与手动选择入口。上次定位时间和精度保留在设置；自动刷新期间或失败后首页暂不显示旧位置对应的日照，避免误认作当前结果。关闭或切换手动地点会取消请求，迟到回调不得覆盖新选择；原生请求使用跨页面不复用的随机标识，并记录有界取消消息，处理取消先于启动的 IPC 顺序。

`preferences.sunlight` 只保存模式和用户手动选择的参考点；自动定位的经纬度、精度、时间及地址只放在本次会话内存，不进入偏好文件、localStorage 或日志，不提供位置上传服务器。系统或浏览器定位服务、Apple 系统地名解析可能联网并按其平台规则处理位置；这不等于定位服务本身完全离线。

## 手动国内地点

内置 1,772 个国内城市及部分区县参考点，来自 GeoNames 的 `cities15000` 快照，采用 WGS84；搜索和计算在资源已载入后可离线使用。数据不是完整行政区划，可能缺少区县或保留旧地名；找不到时可尝试附近城市或使用当前位置。

手动选择在设置中始终标注“地点参考值”，不伪装成精确定位。自动定位补充的“附近”地名只作标签，计算仍使用系统坐标。地点分包在首次搜索或补充附近名称时按需加载，不随首屏请求；分包失败有局部回退，日历和自动定位仍可使用。网页尚未提供 Service Worker，首次打开及首次加载分包仍需要网络。

来源：[GeoNames](https://www.geonames.org/)、[下载与字段说明](https://download.geonames.org/export/dump/)，许可证 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。原始 ZIP 摘要、获取日期及转换说明在 `packages/calendar-core/src/data/china-places-source.json`，更新脚本为 `scripts/import-sunlight-places.mjs`。

## 日照计算口径

公共核心 `getSunlight` 使用锁定的 [SunCalc 2.1.1](https://github.com/mourner/suncalc)（BSD-2-Clause），规则标识为 `suncalc-2.1.1-beijing-v1`。只输入日期与经纬度，不访问位置服务、网络、文件系统或 UI。

- 支持 1901—2100 年，按 UTC+8 民用日计算，不随设备时区或历史夏令时改变。
- 采用太阳上缘经过理想地平线、标准折射、观察高度为零的口径；不将设备海拔当作高于地平线的观察高度。不预测山体、建筑、天气遮挡或实际肉眼可见时刻。
- 日出日落截断秒，以 `HH:mm` 显示；白昼由事件瞬间计算后取整分钟，因此用两个展示时间直接相减可能相差一分钟。
- 极昼、极夜明确返回无升落事件及全天/零白昼，不输出 Invalid Date；仅有单侧事件的日期返回 `partial`。这是核心边界处理，不代表内置国内地点存在极昼极夜。

测试中的独立参考为 [USNO 北京夏至结果](https://aa.usno.navy.mil/api/rstt/oneday?date=2026-06-21&coords=39.9,116.4&tz=8)，并覆盖同城不同经度、国内东西南北地点、设备时区、闰日、支持年份边界与极昼极夜。不能据此宣称所有地点和日期均与天文台逐项核验。

## 验证边界

浏览器以固定公共地点模拟精确/粗略定位、拒绝权限和分包失败，不获取真实用户位置；真实 WKWebView 隔离冒烟验证共享计算、日期切换、定位 IPC 与阻止真实权限请求的保护，并继续完整窗口轨迹及生命周期检查。这些检查不替代实际 Mac 系统授权弹窗、真实定位精度、最低系统、手机 Safari 或 iOS 真机验收；首次实际使用仍需用户在操作系统或浏览器中允许定位。

权限流程参考：[Apple 使用期间授权](<https://developer.apple.com/documentation/corelocation/cllocationmanager/requestwheninuseauthorization()>)与[授权变化回调](<https://developer.apple.com/documentation/corelocation/cllocationmanagerdelegate/locationmanagerdidchangeauthorization(_:)>)。
