# 拾日历 0.1.0 验证记录

验证日期：2026-11-11。环境：Apple Silicon macOS，Swift 6.1.2 / Command Line Tools，Node 24.18.0。

已通过：

- TypeScript 严格类型检查及 ESM、JavaScriptCore 构建。
- 12 项核心测试：农历年界、腊月廿九除夕、闰月、2033闰冬月、补班覆盖周末、缺失调休、2027跨年假期、连休周末、清明/节气、日期校验及时区、月历边界、导入失败保留旧数据、跨年通知覆盖、结果可序列化和缓存隔离（部分测试合并多个场景）。
- macOS 系统 JavaScriptCore 实际调用验证：农历、月历、假期、年度列表、无效输入异常和恢复。
- 实际 SwiftUI/AppKit 视图及状态验证：浅色、深色、春节休班、设置、缺失年份；导航、回到今天和每周起始日断言。
- 独立界面审查：六项已列修复均 resolved，最后 verdict 为 ship；该结论限于截图和已列修复。
- 打包后的 NSPopover 实际打开、关闭、重新打开生命周期验证。
- ad-hoc 签名完整性校验；ZIP 解压到另一目录后再次通过弹层生命周期验证，确认无需依赖构建目录中的资源。
- 可分发核心 tgz 在独立消费工程中的安装、exports、农历及调休查询。

验证边界：

- 菜单栏应用的 CUA 窗口读取有超时限制，因此未用该工具完成真实鼠标点击/键盘焦点/VoiceOver 的端到端操作验证。
- 原生快照在完成 NSApplication 初始化并显示 NSHostingView 后捕获，避免未显示视图产生字形缓存残片；它们是实际原生视图捕获，不是生成的概念图。
- 没有完整 Xcode，未运行 XCTest、iOS 模拟器或真机；已提供可供 macOS/iOS 使用的共享 Swift Package，但未交付 iOS 界面。
- 当前是 arm64 macOS 13+ 本机开发版，未做 Developer ID 签名和 Apple 公证。
- 网络更新有错误处理和离线回退；未通过真实 UI 覆盖所有网络故障和导入面板操作。
